# BTC Radar Orchestrator

BTC 타이밍 레이더 정적 사이트의 변경 작업을 에이전트 협업으로 수행하는 통합 스킬.

## 실행 모드: 서브 에이전트 (생성-검증 순차)

리더가 Agent 도구로 에이전트를 호출하고 반환값으로 조율한다. 2026-06-11 실행 테스트로 확정한 모드다 — 환경 제약(아래) 때문에 에이전트 팀 모드는 현재 실행 불가하다. 생성-검증(Producer-Reviewer) 패턴: 구현 에이전트 → 검증 에이전트 → 결함 시 수정 에이전트 반려 루프(최대 2회).

## 환경 제약 (2026-06-11 실행 테스트로 확인된 사실)

이 제약들은 추정이 아니라 실측이다. 위반하면 같은 실패를 반복한다.

1. **팀 도구 부재**: TeamCreate/SendMessage(팀 통신)/TeamDelete가 이 환경에 없다. 에이전트 간 직접 통신 불가 → 모든 조율은 리더 경유, 데이터 전달은 반환값 + `_workspace/` 파일
2. **커스텀 에이전트 타입은 세션 시작 시 로드**: 세션 중 생성·수정한 `.claude/agents/` 타입은 `subagent_type`으로 호출 불가 → `general-purpose`로 스폰하고 프롬프트 첫 단계에서 에이전트 정의 파일(절대 경로)을 읽게 한다
3. **서브 에이전트 샌드박스 제한**: python3 스크립트 실행과 Playwright MCP가 권한 거부될 수 있다 → 결정적 스크립트(check_bindings, dump_schema)는 **리더가 직접 실행**해 결과를 에이전트 프롬프트에 넣어주고, 렌더링 검사는 에이전트 실패 시 리더가 직접 수행한다
4. **에이전트 연속 대화 불가**: SendMessage가 없으므로 결함 반려는 **새 Agent 호출**에 [이전 변경 요약 + 결함 리포트 + 수정 대상 절대 경로]를 담아 보낸다
5. **worktree 격리 시 리더 셸 cwd 이동**: worktree 격리 에이전트를 스폰하면 리더의 persistent shell cwd가 그 worktree로 이동할 수 있다 → 리더는 항상 절대 경로를 사용한다
6. **worktree는 origin/main 기준**: 미커밋 변경(.claude/ 포함)이 worktree에 없다 → 에이전트에게 스킬·정의·요구사항 파일은 메인 저장소 절대 경로로 준다

## 에이전트 구성

| 에이전트 | 스폰 방법 | 역할 | 스킬 | 출력 |
|---------|----------|------|------|------|
| dashboard-developer | general-purpose + `agents/dashboard-developer.md` 로드 | 대시보드 기능 구현 | btc-dashboard-feature | 코드 수정 + 변경 요약(반환값) |
| content-editor | general-purpose + `agents/content-editor.md` 로드 | 페이지 콘텐츠·SEO | btc-content-seo | 코드 수정 + 변경 요약(반환값) |
| qa-validator | general-purpose + `agents/qa-validator.md` 로드 | 경계면·렌더링 검증 | btc-data-qa | `_workspace/{NN}_qa_report.md` |

모든 Agent 호출에 `model: "opus"` 명시. 작업 성격에 따라 축소: 기능만이면 developer+qa, 콘텐츠만이면 content+qa.

## 워크플로우

### Phase 0: 컨텍스트 확인 (후속 작업 지원)

1. `_workspace/` 존재 여부 확인
2. 실행 모드 결정:
   - **미존재** → 초기 실행, Phase 1로
   - **존재 + 부분 수정 요청** (예: "모바일만 다시", "QA만 재실행") → 해당 에이전트만 스폰, 이전 산출물 경로를 프롬프트에 포함
   - **존재 + 새 작업 요청** → 기존 `_workspace/`를 `_workspace_prev_{YYYYMMDD}/`로 이동 후 초기 실행
3. 이전 결과가 적용 대기 중인 worktree에 있으면(미머지) 사용자에게 먼저 확인

### Phase 1: 준비 (리더 직접)

1. 요청 분석 — 기능/콘텐츠/검증 중 필요한 축 판별. **기존 페이지를 교체·재디자인하는 작업이면(=리디자인) 아래 0번 "무손실 원칙"이 최우선 적용된다.**
2. `git status` 확인 — **메인 작업트리에 미커밋 변경이 있으면 구현 에이전트는 worktree 격리(`isolation: "worktree"`)로 스폰**해 변경이 섞이지 않게 한다. 깨끗하면 메인 트리에서 직접 작업 가능
3. 리더가 `dump_schema.py`로 관련 키 shape 확인 (에이전트 샌드박스 제한 대비, 결과를 요구사항에 포함)
4. **(리디자인 시 필수) 패리티 인벤토리 작성** — 교체 대상 원본 페이지에서 아래를 빠짐없이 추출해 `_workspace/00_input/{page}_parity.md`에 기록하고, request.md에 "이 목록을 100% 보존하라(디자인만 바꾼다)"고 명시한다. 추출 항목:
   - **내부 링크 전부** (`grep -oE 'href="[^"]+"'` — 특히 하위 상세페이지/지표 링크. 개수까지 적는다)
   - **콘텐츠 섹션 전부** (h1~h3 제목, 카드/표/FAQ/면책/CTA 등 — 빠진 섹션이 없게)
   - **노출 데이터 포인트** — 원본이 참조하는 **snapshot 키 집합**을 기계적으로 추출해 인벤토리에 박아둔다: `grep -oE 'api_[a-z_]+' 원본.html | sort -u`. 이 키 집합 전부가 V2에 있어야 한다(없으면 그 키가 채우던 카드가 누락된 것). 추가로 데이터 컨테이너 `id="..."`·`<h2>/<h3>` 목록도 추출. (대시보드 같은 데이터 페이지에서 가장 자주 누락되는 지점 — 디자인 시안이 데이터 카드 일부를 생략하기 때문)
   - **SEO 자산** (title/description/canonical/og/twitter/JSON-LD 구조화데이터)
   - 의도적으로 제거할 항목이 있으면 **사용자에게 먼저 확인**. 임의 누락 금지.
5. `_workspace/00_input/request.md` 작성 — 요구사항 + 데이터 shape + 함정(타입 불일치 등) + (리디자인 시) 패리티 인벤토리 경로·"무손실" 지시 명시

> **0. 리디자인 무손실 원칙 (최우선):** 재디자인은 **오직 디자인(레이아웃·스타일)만** 바꾼다. 기존에 노출되던 데이터·링크·콘텐츠·SEO는 **하나도 빠뜨리지 않고** 그대로 제공해야 한다. "새 디자인에 그 요소가 없다"는 누락의 사유가 되지 않는다 — 원본에 있으면 V2에도 있어야 한다. 신규 디자인 시안이 일부만 담고 있어도, 누락된 기존 요소는 디자인 톤에 맞춰 반드시 이식한다.

### Phase 2: 구현 (서브 에이전트)

Agent 호출 파라미터:
- `subagent_type: "general-purpose"`, `model: "opus"`, `run_in_background: true`(병렬 필요 시)
- 미커밋 변경 존재 시 `isolation: "worktree"`
- 프롬프트 필수 요소: ① 에이전트 정의 파일 절대 경로(첫 단계로 읽기) ② 스킬 절대 경로 ③ request.md 절대 경로 ④ "원본 저장소 수정 금지, worktree 안에서만"(격리 시) ⑤ 반환 형식: worktree 경로 + 수정 파일 + 사용 키 경로 + 새 DOM id + 배치 이유
- 독립적인 기능·콘텐츠 작업은 단일 메시지에서 병렬 스폰

### Phase 3: 검증 (서브 에이전트 + 리더 보완)

1. 리더가 worktree(또는 메인)에서 `check_bindings.py` 직접 실행 — 1차 게이트
2. 리더가 로컬 서버 가동: `python3 -m http.server 8765 -d {대상 디렉토리}` (백그라운드)
3. qa-validator 스폰 — 프롬프트에 ① 정의·스킬 경로 ② 구현 변경 요약 ③ 서버 URL ④ "스크립트/Playwright 거부 시 정적 검사로 대체하고 미검증 명시"
4. **QA가 렌더링 미검증으로 반환하면 리더가 직접 Playwright로 보완**: 콘솔 에러 → 카드 실값 렌더 → 390×844 모바일 → 스크린샷 2장을 `_workspace/`에 저장
5. 렌더링 검증에서는 **단위·스케일 의미**까지 확인 (shape 통과 ≠ 정확한 표시 — btc-data-qa 스킬 참조)
6. **(리디자인 시 필수) 패리티 게이트** — Phase 1의 `{page}_parity.md`를 기준으로 원본 대비 V2의 무손실을 교차 검증한다. 반드시 **세 가지를 기계적으로 diff**:
   - **내부 링크**: 원본 N개 = V2 N개 (`diff <(grep href ...)`)
   - **데이터 키**: `comm -23 <(grep -oE 'api_[a-z_]+' 원본|sort -u) <(grep -oE 'api_[a-z_]+' V2|sort -u)` 출력이 **빈 값**이어야 함 (대시보드 리디자인 필수)
   - **섹션/데이터 컨테이너**: h2·id 목록 diff
   하나라도 빠지면 **[HIGH] 결함으로 반려**(Phase 4). 이 게이트를 통과하지 못하면 절대 PASS 판정하지 않는다. (btc-data-qa 스킬의 "리디자인 패리티 검사" 절차 사용)

### Phase 4: 결함 반려 루프 (최대 2회)

결함 발견 시 새 Agent 호출(연속 대화 불가)로 반려:
- 프롬프트: "이전 세션의 연속 — QA 결함 반려 수정" + 결함 리포트([심각도] 위치/현상/원인/증거/기대) + 수정 대상 절대 경로 + "결함 지점만 최소 수정" + "수정 라인 before→after 반환"
- 수정 후 리더가 해당 항목만 재검증 (서버 재가동 → 브라우저 확인)
- 2회 초과 시 리더가 직접 수정

### Phase 5: 통합 판정·정리·보고 (리더 직접)

1. qa_report + 리더 검증 결과 전 항목 PASS 확인
2. 서버 종료(TaskStop), 브라우저 닫기, `_workspace/` 보존
3. **worktree 격리였다면**: 변경은 worktree 브랜치에 있다 — 사용자에게 메인 반영 여부 확인 (`git diff` 패치 적용 또는 cherry-pick). 임의로 머지하지 않는다
4. 사용자 보고: 변경 파일, QA 결과, 스크린샷 경로, 발견된 기존 이슈(백로그 후보)
5. **커밋은 사용자가 요청한 경우에만**: `git pull --rebase` 후 커밋 (cron의 snapshot 커밋과 충돌 방지)
6. 피드백 기회 제공: "결과나 워크플로우에서 개선할 부분이 있나요?"

## 데이터 흐름

```
[리더] → _workspace/00_input/request.md (+ 리더가 확인한 데이터 shape)
   → Agent(developer, worktree) → 반환값: 변경 요약
   → 리더: check_bindings + 서버 가동
   → Agent(qa) → _workspace/{NN}_qa_report.md (+ 미검증 항목)
   → 리더: 렌더링 보완 검증 → _workspace/{NN}_leader_verification.md
   → 결함 시: Agent(수정, 컨텍스트 요약 포함) → 리더 재검증
   → 리더: 통합 판정 → 사용자 보고 (worktree 반영 여부 확인)
```

## 에러 핸들링

| 상황 | 전략 |
|------|------|
| 에이전트 1개 실패 | 1회 재시도(같은 프롬프트), 재실패 시 리더가 직접 수행하고 보고에 명시 |
| 커스텀 타입 not found | general-purpose + 정의 파일 로드로 즉시 폴백 (확정된 표준 경로) |
| 에이전트가 스크립트/브라우저 권한 거부 보고 | 리더가 해당 검사를 직접 수행, 결과를 산출물에 병합 |
| snapshot에 필요한 키 없음 | 기능 범위 축소(폴백 UI만) 후 사용자 보고 — 백엔드(invest-view)는 이 저장소 밖 |
| 수정-검증 2회 초과 핑퐁 | 리더가 결함 원인 직접 분석 후 직접 수정 |
| cron 커밋과 충돌 | `git pull --rebase` 후 재시도, snapshot.json은 항상 원격 버전 채택 |

### 정상 흐름 (기능 추가, 실측)
1. 미사용 키(api_dashboard_altcoin) 선정 → request.md에 shape + 함정(문자열 숫자) 명시
2. developer를 worktree 격리로 스폰 (메인 트리에 미커밋 변경 존재) → index.html +60줄
3. 리더 check_bindings PASS → 서버 가동 → qa 스폰
4. qa: shape·폴백·배치 PASS, 렌더링은 샌드박스 거부로 미검증 반환 → 리더가 Playwright 보완
5. 리더 검증에서 단위 결함(×100) 발견 → 수정 에이전트 반려 → 1회 만에 수렴
6. 산출물: worktree 브랜치 + `_workspace/` 리포트 3건 + 스크린샷 2장

### 에러 흐름 (실측 사례들)
- 커스텀 타입 'dashboard-developer' not found → general-purpose 폴백으로 정상 진행
- 에이전트 python3 거부 → 수동 로직 검증으로 대체 + "미실행" 명시, 리더가 스크립트 실행으로 보완
- QA Playwright 거부 → 정적 검사만 수행 + "미검증" 분리 보고, 리더가 렌더링 보완
